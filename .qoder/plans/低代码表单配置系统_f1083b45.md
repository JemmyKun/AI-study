# 低代码表单配置系统

## 技术选型

| 领域 | 选择 | 理由 |
|------|------|------|
| 框架 | React 18.x + TypeScript 4.9.5 | 与 antd 4.x 官方兼容，生态成熟稳定 |
| UI 组件库 | antd 4.x (^4.24.16) + @ant-design/icons | 兼容老项目需要，Form/Row/Col 组件完善，LESS 样式体系；图标需单独安装 |
| 样式方案 | LESS + craco + babel-plugin-import | 用户指定 LESS；craco 覆盖 CRA webpack 配置；babel-plugin-import 实现 antd 按需加载减小打包体积 |
| 样式前缀 | `lcf-` | 所有自定义 className 统一添加 `lcf-` 前缀（如 `lcf-form-builder`、`lcf-field-renderer`），防止与 antd 全局样式冲突 |
| 拖拽库 | @dnd-kit/core + @dnd-kit/sortable | 现代轻量、TS 友好、无障碍支持好，比 react-dnd 更简洁 |
| 路由 | react-router-dom v6 | 用于设计器和渲染器页面切换 |
| 状态管理 | React hooks (useReducer) | 项目规模适中，无需引入 Redux/Zustand |
| 唯一 ID | nanoid | 轻量，用于生成组件 ID |

## 组件注册表设计（Component Registry）

这是系统的核心扩展机制，支持**注册自定义组件类型**和**覆盖默认组件**。

```typescript
// src/registry/types.ts

/** 注册组件的配置 */
interface ComponentConfig {
  /** 组件类型唯一标识 */
  type: string;
  /** 组件显示名称（设计器面板中使用） */
  label: string;
  /** 组件图标（设计器面板中使用） */
  icon?: React.ReactNode;
  /** 分类（设计器面板分组） */
  category: 'basic' | 'select' | 'date' | 'layout' | 'custom';
  /** 实际渲染的 React 组件 */
  component: React.ComponentType<any>;
  /** 默认属性（新拖入时自动填充） */
  defaultProps?: Partial<FormField>;
  /** 该组件支持的属性配置项（控制 PropertyEditor 中显示哪些配置） */
  configurableProps?: string[];
}

// src/registry/componentRegistry.ts

class ComponentRegistry {
  private registry: Map<string, ComponentConfig> = new Map();

  /** 注册新组件类型 */
  register(config: ComponentConfig): void;

  /** 批量注册 */
  registerAll(configs: ComponentConfig[]): void;

  /** 覆盖已有类型的组件实现（如 input → FbInput） */
  override(type: string, component: React.ComponentType<any>): void;

  /** 获取组件配置 */
  get(type: string): ComponentConfig | undefined;

  /** 获取全部已注册组件（设计器面板使用） */
  getAll(): ComponentConfig[];

  /** 按分类获取（设计器面板分组使用） */
  getByCategory(): Map<string, ComponentConfig[]>;
}

// 单例导出
export const componentRegistry = new ComponentRegistry();
```

**使用示例：**

```typescript
import { componentRegistry } from './registry/componentRegistry';
import './registry/defaultComponents'; // 导入即注册默认组件

// 新增自定义组件类型
componentRegistry.register({
  type: 'amtInput',
  label: '金额输入',
  icon: <DollarOutlined />,
  category: 'custom',
  component: AmtInput,
  defaultProps: { span: 12, placeholder: '请输入金额' },
});

// 覆盖默认组件（input → FbInput）
componentRegistry.override('input', FbInput);
```

## 表单 Schema JSON 结构

```typescript
interface FormSchema {
  version: string;               // schema 版本号（如 '1.0.0'），用于未来兼容迁移
  title: string;
  description?: string;
  labelCol?: number;           // 标签列宽 (1-24)
  wrapperCol?: number;         // 控件列宽 (1-24)
  fields: FormField[];
}

interface FormField {
  id: string;
  type: string;                 // 组件类型标识，对应注册表中注册的 type（不再限制为固定枚举，支持自定义扩展）
  label: string;
  name: string;
  placeholder?: string;
  required?: boolean;
  defaultValue?: any;
  span: number;               // 栅格列宽 (1-24)
  /** 静态选项（与 dataSource 互斥，优先级低于 dataSource） */
  options?: { label: string; value: string }[];
  /** 动态数据源配置（如字典接口） */
  dataSource?: DataSourceConfig;
  rules?: ValidationRule[];
  linkages?: LinkageRule[];
  /** list 类型专用：子字段模板（每一行包含的字段定义） */
  children?: FormField[];
  /** list 类型配置 */
  listConfig?: {
    min?: number;               // 最少项数
    max?: number;               // 最多项数
    addText?: string;           // 添加按钮文字
  };
  [key: string]: any;          // 自定义组件的额外属性
}

/** 数据源配置 */
interface DataSourceConfig {
  /** 数据源类型：static 使用 options 字段，api 通过接口动态获取 */
  type: 'static' | 'api';
  /** api 模式：请求 URL（支持模板变量如 /api/dict/{dictType}） */
  url?: string;
  /** api 模式：请求方法 */
  method?: 'GET' | 'POST';
  /** api 模式：额外请求参数 */
  params?: Record<string, any>;
  /** api 模式：从响应 JSON 中提取选项数组的路径（如 'data.list'、'result.items'） */
  dataPath?: string;
  /** api 模式：选项的 label 字段名（默认 'label'） */
  labelField?: string;
  /** api 模式：选项的 value 字段名（默认 'value'） */
  valueField?: string;
}

/** 字段校验规则 */
interface ValidationRule {
  type: 'required' | 'min' | 'max' | 'minLength' | 'maxLength' | 'pattern' | 'custom';
  value?: any;                   // 规则参数（如 min 的数值、pattern 的正则字符串）
  message: string;               // 校验失败提示消息
}

interface LinkageRule {
  /** 触发字段 name */
  triggerField: string;
  /** 模式：'rule' 基于条件/动作配置，'handler' 调用注册表中的自定义处理器 */
  mode?: 'rule' | 'handler';
  /** rule 模式：条件列表 */
  conditions?: { operator: 'eq' | 'neq' | 'gt' | 'lt' | 'contains' | 'notContains'; value: any }[];
  /** rule 模式：动作列表 */
  actions?: { targetField: string; type: 'visible' | 'hidden' | 'disabled' | 'enabled' | 'required' | 'setValue' | 'setOptions'; value?: any }[];
  /** handler 模式：引用注册表中已注册的联动处理器 ID */
  handlerId?: string;
}
```

## 联动处理器注册表设计（Linkage Handler Registry）

联动系统支持两种模式，可混合使用：

- **规则模式（rule）**：通过 JSON 配置 conditions/actions，适合简单场景，可由设计器可视化编辑
- **处理器模式（handler）**：注册自定义函数，适合复杂业务逻辑，完全可扩展

```typescript
// src/registry/linkageRegistry.ts

/** 联动处理器上下文 */
interface LinkageContext {
  /** 触发变更的字段 name */
  triggerField: string;
  /** 触发字段的新值 */
  triggerValue: any;
  /** 当前表单全部字段值 */
  formValues: Record<string, any>;
  /** antd Form 实例，可调用 setFieldsValue / getFieldInstance 等 */
  form: any;
}

/** 联动处理器返回结果 */
interface LinkageResult {
  [targetFieldName: string]: {
    visible?: boolean;
    disabled?: boolean;
    required?: boolean;
    value?: any;
    options?: { label: string; value: string }[];
  };
}

/** 联动处理器定义 */
interface LinkageHandler {
  /** 处理器唯一 ID */
  id: string;
  /** 显示名称（设计器中使用） */
  label: string;
  /** 描述（设计器提示） */
  description?: string;
  /** 核心处理函数 */
  handler: (ctx: LinkageContext) => LinkageResult;
}

class LinkageRegistry {
  private handlers: Map<string, LinkageHandler> = new Map();

  /** 注册自定义联动处理器 */
  register(handler: LinkageHandler): void;

  /** 批量注册 */
  registerAll(handlers: LinkageHandler[]): void;

  /** 获取处理器 */
  get(id: string): LinkageHandler | undefined;

  /** 获取全部处理器（设计器 LinkageEditor 使用） */
  getAll(): LinkageHandler[];
}

// 单例导出
export const linkageRegistry = new LinkageRegistry();
```

**使用示例：**

```typescript
import { linkageRegistry } from './registry/linkageRegistry';

// 注册自定义联动逻辑：A字段变化时联动修改 B、C
linkageRegistry.register({
  id: 'cascadeAddress',
  label: '地址级联',
  description: '省份变更时联动更新城市和区县选项',
  handler: ({ triggerField, triggerValue, form }) => {
    if (triggerField === 'province') {
      const cities = getCitiesByProvince(triggerValue);
      form.setFieldsValue({ city: undefined, district: undefined });
      return {
        city: { options: cities, visible: true },
        district: { options: [], visible: cities.length > 0 },
      };
    }
    return {};
  },
});

// 在 schema 中引用
const field: FormField = {
  // ...
  linkages: [
    { triggerField: 'province', mode: 'handler', handlerId: 'cascadeAddress' }
  ]
};
```

**联动引擎执行流程（`linkageEngine.ts`）：**
1. 字段值变化时，收集该字段关联的所有 LinkageRule
2. 对 `mode === 'rule'` 的规则，执行条件判断 + 动作执行
3. 对 `mode === 'handler'` 的规则，从 `linkageRegistry.get(handlerId)` 获取处理器并执行
4. 合并两种模式的结果，返回最终的 linkageState

## 实现步骤

### Task 1: 项目基础设施搭建
- **降级 React**: `npm install react@18 react-dom@18 @types/react@18 @types/react-dom@18`（从 19.x 降级到 18.x，与 antd 4.x 完全兼容）
- **安装依赖**: `npm install antd@4 @ant-design/icons @dnd-kit/core @dnd-kit/sortable @dnd-kit/utilities react-router-dom nanoid`
- **配置 LESS 构建**: 安装 `craco` + `craco-less` + `less` + `less-loader` + `babel-plugin-import`，创建 `craco.config.js` 配置 LESS 支持和 babel-plugin-import 按需加载，修改 `package.json` 的 scripts 使用 `craco start/build/test` 替代 `react-scripts`
- **引入 antd 样式**: 在 `src/index.tsx` 中 `import 'antd/dist/antd.less'`（通过 craco-less 支持 LESS 导入）
- **创建 LESS 变量文件**: `src/styles/variables.less` — 定义通用变量和前缀约定
- **创建类型文件**: `src/types/form.ts` — 定义 FormSchema（含 version）、FormField、DataSourceConfig、ValidationRule、LinkageRule、FormRendererProps 等全部类型
- **创建组件注册表**: `src/registry/` 目录，包含：
  - `types.ts` — ComponentConfig 类型定义
  - `componentRegistry.ts` — ComponentRegistry 类（register / override / get / getAll / getByCategory）
  - `defaultComponents.tsx` — 内置默认组件映射（input→Input, textarea→Input.TextArea, select→Select, datePicker→DatePicker, switch→Switch, number→InputNumber, radio→Radio.Group, checkbox→Checkbox.Group, rate→Rate, slider→Slider, **list→特殊容器组件**映射到 Antd Form.List），导入即注册
- **新增路由**: 修改 `src/App.tsx`，添加 react-router-dom 路由：
  - `/` → 首页（导航入口）
  - `/builder` → FormBuilder 设计器
  - `/renderer` → FormDemo 渲染演示
- **注意 antd 4 API 差异**: Form 使用 `Form.useForm()`、`<Form.Item name="x">`；DatePicker 使用 moment.js 而非 dayjs
- **无外部依赖，最先执行**

### Task 2: 设计器核心状态管理
- **创建** `src/components/FormBuilder/useDesigner.ts`
  - 使用 `useReducer` 管理表单 schema 状态
  - 支持操作: addField, removeField, moveField, updateField, selectField, duplicateField
  - **字段 name 唯一性**: duplicateField 时自动生成唯一 name（如 `field_1` → `field_1_copy`，冲突时递增后缀）
  - **撤销/重做**: 维护 history 栈（最多 50 步），支持 Ctrl+Z/Ctrl+Shift+Z 快捷键
  - 支持从组件面板拖入新字段、画布内排序
  - **list 字段操作**: addListChild, removeListChild, updateListChild — 管理列表型字段的子字段模板
  - **保存/加载 schema**: localStorage 持久化 + JSON 文件导入/导出（方便分享和备份）
  - **Schema 校验**: 提供 `validateSchema()` 方法，保存前全量检查，返回错误列表；与 `schemaValidator.ts` 配合使用
  - **确保导入时机**: 在 App.tsx 入口处 `import './registry/defaultComponents'`，保证注册表在渲染前初始化
- **依赖 Task 1 的类型定义**

### Task 3: 联动规则引擎 + Schema 校验
- **创建** `src/registry/linkageRegistry.ts`
  - LinkageRegistry 类（register / registerAll / get / getAll）
  - LinkageHandler、LinkageContext、LinkageResult 类型定义
- **创建** `src/utils/linkageEngine.ts`
  - 函数 `evaluateLinkages(schema, currentValues, formInstance)` → 返回每个字段的联动状态
  - 规则模式：支持操作符 eq/neq/gt/lt/contains/notContains，动作 visible/hidden/disabled/enabled/required/setValue/setOptions
  - 处理器模式：从 linkageRegistry 获取 handler 并执行，传入 LinkageContext
  - 合并两种模式结果
- **创建** `src/utils/schemaValidator.ts`
  - 函数 `validateSchema(schema: FormSchema): ValidationError[]` — 返回全部错误列表
  - 校验项：①每个字段必须有 label 和 name ②字段 name 不能重复 ③select/radio/checkbox 必须有 options 或 dataSource ④list 类型必须有 children ⑤联动规则引用的 triggerField 必须存在 ⑥数据源 API 模式的 url 必填
  - 每个 ValidationError 包含 `{ fieldId, fieldLabel, message, severity }` 便于设计器展示和定位
- **创建** `src/components/FormRenderer/useLinkage.ts`
  - 监听 antd Form 的 onValuesChange，调用 linkageEngine 计算状态
  - 返回 linkageState map 供 FieldRenderer 消费
- **依赖 Task 1**

### Task 4: 表单设计器 UI
- **ComponentPalette.tsx**: 左侧面板，从 `componentRegistry.getByCategory()` 读取已注册组件，按分类展示（带 @dnd-kit useDraggable）
- **DesignCanvas.tsx**: 中间画布，使用 @dnd-kit useDroppable + SortableContext，接受拖入和排序；**list 类型字段渲染为可展开的容器**，内部可拖入子字段模板；**空状态引导**：画布无字段时显示拖拽提示；**V1 限制：list 内不支持嵌套 list**
- **ComponentWrapper.tsx**: 画布中每个组件的包装，提供拖拽手柄、选中高亮、删除/复制按钮
- **PropertyEditor.tsx**: 右侧属性面板，编辑选中字段的 label/name/placeholder/required/span/options/rules 等；**对有选项类组件（select/radio/checkbox）支持配置数据源：静态选项 或 API 动态数据源（URL、method、params、dataPath、labelField、valueField）**；**必填项实时校验提示**：label/name 等必填属性未填时显示红色提示，字段 name 重复时显示冲突警告
- **LinkageEditor.tsx**: 联动规则编辑 UI，支持两种模式：①规则模式（可视化配置条件/动作）②处理器模式（从 linkageRegistry 选择已注册的处理器）
- **PreviewModal.tsx**: 预览弹窗，内部调用 FormRenderer 渲染当前 schema
- **FormBuilder.tsx**: 三栏布局主页面，组合以上组件；**支持预览/编辑模式切换**（工具栏按钮）；**保存时校验**：点击保存时调用 `validateSchema()`，若有错误则弹出错误列表面板（显示每个字段的错误信息，点击可定位到对应字段），无错误才执行保存
- **FormBuilder.less**: 设计器样式（LESS，所有 className 以 `lcf-` 为前缀，如 `.lcf-builder-layout`、`.lcf-palette-item`、`.lcf-canvas-field`）
- **依赖 Task 2, Task 3**

### Task 5: 表单渲染器
- **FieldRenderer.tsx**: 从 `componentRegistry.get(field.type)` 获取组件并渲染，消费联动状态控制 visible/disabled；未注册类型显示警告提示；**当 field.type === 'list' 时委托 ListRenderer 渲染**；**当 field 配置了 dataSource 时通过 useDataSource 获取动态选项**
- **useDataSource.ts**: 动态数据源 Hook，根据 DataSourceConfig 配置调用 API 获取选项数据，支持 URL 模板变量解析、dataPath 响应数据提取、labelField/valueField 字段映射、loading 状态管理；**缓存策略**：基于 URL+params 的内存级缓存（同一页面内相同请求不重复发起，页面刷新后失效）
- **ListRenderer.tsx**: 使用 Antd `Form.List` 实现一对多场景，根据 field.children 模板渲染每一行，支持动态添加/删除行，支持 min/max 限制，每行内字段使用栅格布局
- **GridRenderer.tsx**: 按字段列表解析栅格行（span 累加至 24 换行），使用 Antd Row/Col 渲染
- **FormRenderer.tsx**: 主组件，接收 FormRendererProps（schema/initialValues/onFinish/onValuesChange/readOnly/layout），创建 Antd Form 实例，集成 useLinkage，输出完整表单；**空 schema 降级**：fields 为空时显示友好提示
- **FormRenderer.less**: 渲染器样式（LESS，所有 className 以 `lcf-` 为前缀，如 `.lcf-form-renderer`、`.lcf-field-wrapper`、`.lcf-list-item`）
- **依赖 Task 1, Task 3**

### Task 6: 渲染演示页与集成测试
- **FormDemo.tsx**: 从 localStorage 加载 schema，渲染 FormRenderer，提供返回设计器的导航
- **端到端验证**: 设计器拖拽组件 → 配置属性和联动 → 保存 → 渲染器正确展示并联动生效
- **依赖 Task 4, Task 5**

Task 2 和 Task 3 可并行；Task 4 和 Task 5 可并行；Task 6 必须等 Task 4 和 Task 5 都完成。

## 风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| antd 4.x 与 React 版本兼容 | React 降级到 18.x 后与 antd 4.x 官方兼容，无风险；`@testing-library/react` 需同步降级到 `^14` |
| @dnd-kit 拖拽在画布排序的复杂场景 | 参考官方 sortable grid 示例，限制为单列排序简化复杂度 |
| 联动规则嵌套过深导致性能问题 | 限制规则深度为1层（单条件组），引擎采用 O(n) 遍历 |
| antd 4 全局样式与现有样式冲突 | antd 4 引入全局 `antd.less`，可能与现有 ChatPage.css 冲突；通过 `lcf-` 前缀约定隔离自定义样式，表单模块容器使用 `.lcf-` 前缀包裹，避免类名冲突 |
| Form.List 嵌套复杂度 | V1 版本仅支持一级列表，不支持 list 内嵌套 list；后续版本再考虑多层嵌套 |
| 数据源接口失败降级 | API 请求失败时回退到 options 静态选项，并在控制台输出警告日志 |

## 被否决的备选方案

- **react-dnd**: 功能强大但 API 复杂、TS 支持差、维护不够活跃，对表单拖拽场景过度设计
- **HTML5 原生拖拽 API**: 无需依赖但跨浏览器兼容性差、触摸支持弱、代码量大
- **Redux/Zustand**: 对当前项目规模过重，useReducer 已足够
- **formily/Amis**: 这些本身就是低代码方案，直接使用会架空需求的学习和定制价值
